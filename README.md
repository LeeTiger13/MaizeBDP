# MaizeBDP

MaizeBDP is a server-side maize breeding decision-support platform. It combines genotype-based analysis workflows with MIKA, a language-model-assisted retrieval and knowledge-graph service.

This repository provides the public server implementation, analysis scripts, and representative test data. It is a research software and architecture release rather than a standalone model or a complete data package.

## Platform overview

MaizeBDP has two connected parts:

| Part | Main role |
|---|---|
| `MaizeBDP_Function_Module/` | Genotype pretreatment, genetic-background analysis, breeding guidance, hybrid simulation, and genomic selection |
| `MIKA/` | Natural-language access to literature retrieval and the maize pedigree knowledge graph |

The analysis modules process VCF-based genotype data and generate quality-control reports, genetic-background results, genetic-distance results, breeding-guidance outputs, hybrid-simulation results, and genomic-selection predictions.

MIKA uses a dual-path workflow. A routing model identifies whether a question should be answered through the literature retrieval path or the knowledge-graph path. The retrieval path uses vector search and reranking, while the knowledge-graph path queries maize variety and pedigree relationships in Neo4j. The final answer can be generated by a local model such as Qwen3:14B or by a compatible remote API.

## Typical analysis workflow

```text
VCF input
   |
   v
Genotype pretreatment
   |
   +--> Genetic background and heterotic-group analysis
   |
   +--> Genetic distance and breeding-guidance analysis
   |
   +--> Hybrid simulation and genomic selection
   |
   v
MIKA evidence retrieval and knowledge-graph exploration
```

## Public release scope

The repository includes:

- server-side MIKA code and configuration templates;
- genotype-analysis scripts and representative test data;
- example module layouts and command-line entry points;
- the variety-name mapping used to connect English or abbreviated names with names in the Chinese knowledge graph.

The following production resources are not included:

- the production Neo4j knowledge graph and graph-construction pipeline;
- indexed literature files, vector databases, and retrieval services;
- local model weights and reranker checkpoints;
- private reference panels and breeding datasets;
- API keys, passwords, and service credentials.

The public test data support representative genomic-analysis examples. Complete MIKA functionality requires equivalent user-provided data services and model endpoints.

## Getting started

Clone the repository and choose the workflow you need:

```text
git clone https://github.com/LeeTiger13/MaizeBDP.git
cd MaizeBDP
```

- To run the genotype-analysis modules, prepare the required command-line bioinformatics tools and use the test data in each module.
- To deploy MIKA, provide the model, Neo4j, retrieval, and reranker resources required by your environment.
- For installation steps, hardware requirements, service configuration, and deployment examples, see [DEPLOYMENT.md](DEPLOYMENT.md).

## Name mapping resource

`MIKA/variety_alias.yaml` is intentionally included. It maps English or abbreviated variety names to the Chinese names used in the knowledge graph and supports bilingual variety matching. The Chinese values in this file are expected and are the only non-English content in the public release.
